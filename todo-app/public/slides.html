Section 1 · 마인드셋

AI는 도구다 — 배트를 혼내는 타자는 없다

AI는 확률로 답하는 도구입니다. 틀렸을 때 필요한 건 화풀이가 아니라 더 나은 지시입니다

⚾ 타자와 배트
• 안타를 못 치고 아웃 → 화가 나서 배트를 부순다
• 그런데 배트가 잘못했나요? 배트는 휘두른 대로 맞았을 뿐
• 다음 타석에 필요한 건 새 배트가 아니라 스윙 교정
• 배트를 혼내는 건 그냥 내 분풀이
🤖 사람과 AI
• AI가 엉뚱한 답 → 화가 나서 욕설을 쓴다
• 그런데 AI가 반성할까요? AI는 확률로 다음 답을 고를 뿐
• 욕설은 AI에게 아무 정보도 주지 않음 → 결과는 그대로
• AI는 친구도 적도 아닌 도구 — 인격체로 대하지 말 것
💡 AI가 틀렸을 때의 '스윙 교정': ① 무엇이 틀렸는지 ② 원하는 결과가 무엇인지 ③ 에러 메시지·화면을 그대로 전달하기.
잘 휘두르는 건 결국 사람의 몫입니다.
Section 1 · 개념 이해

바이브 코딩(Vibe Coding)이란?

문법을 외우는 것이 아니라, AI에게 명확한 맥락과 사각지대 없는 의도를 디렉팅하는 개발

⚠️ 잘못된 바이브 코딩
• 지시의 부재 & 사각지대: 빈 공간을 AI가 추측하게 방치
• "알아서 적당히 만들어줘" 식의 모호한 요청
• 플랫폼 하네싱(도구, 터미널, 컨텍스트)을 무시한 소통
• 현상: 환각이 아니라 지시 결손으로 인한 엉뚱한 결과
✨ 올바른 바이브 코딩
• 세세한 디렉팅(Directing): 의도와 제약조건을 명확히 명시
• 스펙 작게 쪼개기: DB 구조 → 화면 UI → 인터랙션 단계 분할
• 도구 기반 피드백: 에러 로그 공유 및 실시간 시각적 검증
• 현상: 사각지대를 메워 신뢰성 높은 결과 도출
💡 "현대 AI 플랫폼의 하네싱(도구 연동, 터미널, 린터)은 이미 강력합니다. 지금 발생하는 오류는 환각이 아니라 '지시의 사각지대'에서 생깁니다."
Section 1 · 도구 이해

💬 챗 vs 🤖 에이전트 — AI 도구는 두 종류다

오늘은 무료 도구로 실습하지만, 도구가 어떻게 나뉘는지는 알고 시작합시다

💬 챗형 (웹사이트)
• claude.ai · ChatGPT · Gemini
• 질문하면 대답해 주는 선생님
• 코드를 받아서 내가 복붙하고, 내가 실행하고, 에러도 내가 다시 질문
• 서비스마다 특기가 다름: ChatGPT·Gemini는 이미지 생성 가능, Claude는 글·코드 설명에 강점
🤖 에이전트형 (CLI · IDE)
• 안티그래비티(오늘 실습) · Claude Code · Codex CLI · Gemini CLI
• 내 컴퓨터에서 같이 일하는 동료
• 파일을 직접 읽고 고치고, 직접 실행하고, 에러도 스스로 수정
• 사람은 지시하고 검토하는 '디렉터' 역할
💡 조합 예시: ChatGPT로 프로필 이미지 생성 → 프로젝트 폴더에 저장 → 안티그래비티에게 "이 사진을 이력서 상단에 넣어줘"
만들어내기는 챗에서, 내 프로젝트에 적용하기는 에이전트에게.
Section 1 · 현업 이야기

티끌 모아 티끌 — 무료만 모아서는 현업이 안 된다

오늘은 무료로 충분합니다. 하지만 일로 하려면 이야기가 달라집니다

🪙 무료의 현실 = 티끌
• 무료 사용량은 작업 도중에 끊김: "한도 초과, ○시간 뒤 다시 시도"
• A 한도가 끝나면 B로, B가 끝나면 C로 옮겨 다님
• 옮길 때마다 처음부터 다시 설명 (맥락이 끊김)
• 무료 계정 10개를 모아도 결과는 티끌 10개, 태산이 되지 않음
🏔️ 현업의 방식 = 끊기지 않는 흐름
• 현업 개발자는 터미널(CLI)에서 에이전트와 하루 종일 일함
• 하나의 도구가 프로젝트 전체 맥락을 들고 끝까지 이어서 작업
• 한도 걱정 없이 만들고 → 실행하고 → 고치고를 수십 번 반복
• 목표는 웹페이지 하나가 아니라 이 흐름에 익숙한 사람이 되는 것
