Section 1 · 개념 이해

바이브 코딩(Vibe Coding)이란?

문법을 외우는 것이 아니라, AI에게 명확한 맥락과 사각지대 없는 의도를 디렉팅하는 개발

⚠️ 잘못된 바이브 코딩
• 지시의 부재 & 사각지대: 빈 공간을 AI가 추측하게 방치
• "알아서 적당히 만들어줘" 식의 모호한 요청
• 플랫폼 하네싱(도구, 터미널, 컨텍스트)을 무시한 소통
• 현상: 환각이 아니라 지시 결손으로 인한 엉뚱한 결과
✨ 올바른 바이브 코딩
• 세세한 디렉팅(Directing): 의도와 제약조건을 명확히 명시
• 스펙 작게 쪼개기: DB 구조 → 화면 UI → 인터랙션 단계 분할
• 도구 기반 피드백: 에러 로그 공유 및 실시간 시각적 검증
• 현상: 사각지대를 메워 신뢰성 높은 결과 도출
💡 "현대 AI 플랫폼의 하네싱(도구 연동, 터미널, 린터)은 이미 강력합니다. 지금 발생하는 오류는 환각이 아니라 '지시의 사각지대'에서 생깁니다."
Section 2 · 15분 환경 세팅

실패 확률 0% 환경설정 체크 & Git 지뢰 대처

오늘 우리는 복잡한 터미널 인증 트라우마를 한 방에 통과하는 방법을 씁니다.

🐙 1. GitHub 계정 단일화
Supabase, Vercel 모두 [Continue with GitHub]로 1초 소셜 로그인
💻 2. GitHub Desktop 추천
초보자의 PAT/SSH 터미널 토큰 인증 에러를 100% 회피
🛡️ 3. OS별 스크립트 권한
🪟 Win: `Set-ExecutionPolicy RemoteSigned`
🍎 Mac: 게이트키퍼 우클릭 [열기]
⚠️ 실전 단골 지뢰 (403 Forbidden 권한 에러)
컴퓨터에 다른 GitHub 계정이 저장되어 있으면 푸시할 때 Permission denied to ... 에러가 발생합니다.
👉 해결법: 윈도우 자격 증명 관리자에서 이전 계정을 삭제하거나, 저장소 Settings > Collaborator에서 현재 계정을 협업자로 초대(Invite)하면 즉시 해결됩니다.

Supabase 2: 최신 API 키 복사 & SQL 테이블 생성

변경된 최신 UI에서 Publishable Key를 복사하고 3줄 SQL로 테이블을 완성합니다.

🔑 최신 UI: Publishable Key 복사
Supabase가 anon key를 Publishable key(공개 가능 키)로 명칭을 개편했습니다. sb_publishable_... 옆 복사 버튼을 누르세요. (아래의 Secret key는 절대 금지!)
-- SQL Editor에 복붙 후 [Run] 클릭! create table if not exists todos ( id bigint generated by default as identity primary key, title text not null, is_completed boolean default false, created_at timestamp with time zone default timezone('utc'::text, now()) not null ); alter table todos enable row level security; create policy "Public Access" on todos for all using (true) with check (true);
💡 .env에 바로 적용: 복사한 Project URL과 Publishable Key를 프로젝트의 .env 파일에 붙여넣습니다.

Section 4 · 배포 2단계

Vercel 배포 2: 404 NOT FOUND와 Root Directory 지뢰

빌드 시간이 1초(1s)로 끝나고 흰 404 화면이 떴을 때 10초 만에 해결하는 법

⚠️ 왜 404 에러가 떴을까?
Vercel은 기본적으로 최상위 루트(`./`)의 index.html을 찾습니다. 하지만 우리 프로젝트는 todo-app 하위 폴더 안에 들어있기 때문에 홈페이지를 찾지 못한 것입니다.
🛠️ 10초 해결법: Root Directory 변경
프로젝트 Settings > Build and Deployment 메뉴로 이동
👉 Root Directory 항목의 [Edit]을 눌러 `todo-app`을 입력하고 [Save]!
💡 강의 시 팁: 실제 학생 강의 시에는 저장소 루트에 바로 Vite 프로젝트를 생성시키면 이 단계 자체가 생략되어 완전한 원클릭 배포가 됩니다.
📷 9. Duration 1s & 404 NOT_FOUND 현상
📷 10. Root Directory를 todo-app으로 지정
Section 4 · 배포 3단계

Vercel 배포 3: Environments 함정과 Config vs Secret 원리

수강생들이 가장 멘붕에 빠지기 쉬운 환경변수 2대 지뢰를 완벽히 격파합니다.

함정 1: `Environments` 팝업 (Pro 결제 유도?)
Settings의 Environments를 누르면 '소문자만 가능', 'Upgrade to Pro' 팝업이 뜹니다. 이는 유료 스테이징 환경 기능입니다.
👉 해결: 메인 사이드바의 `X= Environment Variables`로 가야 진짜 무료 환경변수 등록창이 나옵니다.
함정 2: `VITE_` 변수는 왜 무조건 Config인가?
VITE_ 접두사는 브라우저 JS 번들에 구워져 전 세계에 공개되는 변수입니다. Vercel은 공개될 변수를 `Secret`으로 감추는 착각을 막기 위해 무조건 `Config`를 강제합니다.
👉 VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY 둘 다 `Config`로 등록!

📷 12. VITE_ 변수는 visibility: config 필수 에러
📷 13. 진짜 환경변수 메뉴에서 Config로 등록
